Recruiting & Vacancy Performance

A synthetic recruiting data model to analyze open roles, candidate conversion, time-to-fill, and aging vacancies.

Business problem

Hiring teams need to see which vacancies are aging, where candidates drop out of the process, and how long roles take to fill, so recruiters can act on stalled roles before hiring managers escalate.

Objective: a reporting model with one documented definition per KPI and an automated alert for vacancies above an aging threshold.

Data model

Use synthetic records only. Suggested tables: jobs, candidates, applications, recruiters. Give each entity a stable ID and define the grain of each table before joining.

TableGrainKey fields
jobsOne row per vacancycreated_at, closed_at, status, department, recruiter_id
candidatesOne row per synthetic candidatecandidate_id, no unnecessary personal attributes
applicationsOne candidate applying to one jobsource, applied_at, current_stage, hired_at, rejected_at
recruitersOne row per recruiterrecruiter_id

See the proposed data model.

KPIs

  • Open vacancies as of the reporting date
  • Time-to-fill, with a documented start and end date
  • Application-to-interview and interview-to-hire conversion
  • Vacancy aging buckets and stale-update alerts
  • Candidate source effectiveness, with sample-size caveats

Funnel definitions

Automation plan

Build an n8n workflow that checks open roles daily, identifies roles above a configurable aging threshold, logs each run, and sends a test alert. Mark it as implemented only after it runs successfully.

  1. Daily triggerScheduled run reads open vacancies.
  2. Threshold checkRoles above the configurable aging limit are flagged.
  3. Log and alertEach run is logged; flagged roles send a test alert.

Dashed steps are planned and not yet implemented.

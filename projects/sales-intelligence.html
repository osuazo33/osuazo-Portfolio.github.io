Business problem

Business stakeholders need a consistent view of orders, item revenue, payment totals, and delivery performance. Joining raw tables without controlling their grain can inflate totals, so the project separates order items and payments before joining them to orders.

Objective: one validated monthly reporting view that a dashboard can read without re-implementing metric logic, with every definition written down.

Data source

Brazilian E-Commerce Public Dataset by Olist. Source: Kaggle dataset page ↗. Review and comply with the dataset license (CC BY-NC-SA 4.0). The data is Brazilian and is used as a technical example, not as a proxy for US market behavior.

Tables used: olist_orders_dataset, olist_order_items_dataset, olist_order_payments_dataset, olist_customers_dataset, olist_products_dataset.

Why grain matters

An order can have several items and several payments (instalments, vouchers). Joining both tables straight to orders multiplies rows: every item is repeated for every payment.

Architecture

  1. SourceCSV files imported into a dedicated BigQuery dataset.
  2. TransformSQL staging and reporting queries with explicit grain and metric definitions.
  3. ValidateUniqueness, missing values, referential integrity, and reconciliation checks.
  4. ReportLooker Studio dashboard connected to a verified reporting view.
  5. AutomateAdd n8n orchestration, execution logging, and failure notification once implemented.
  6. MonitorRecord run timestamp, row counts, failed checks, and action taken.

Limitations

  • Missing values and canceled or unavailable orders must be documented, not silently dropped.
  • Date coverage is limited to the dataset's collection period.
  • Item revenue and payment totals measure different things and are not expected to match.
  • Steps that remain manual are listed until automation exists.

Reproducibility

Load the CSVs into BigQuery, then run the queries in order: profiling, KPIs, quality checks. Exact table names, required permissions and the dashboard link are documented in the README. Never include service account keys or other secrets.

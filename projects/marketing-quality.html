Business problem

Marketing reports are only as good as the event data behind them. Missing identifiers, duplicated purchases or a silent tracking outage can make a campaign look better or worse than it is.

Objective: a documented product funnel and a set of quality checks that run before anyone reads conversion or revenue figures.

Data source

Google Analytics 4 public ecommerce sample: bigquery-public-data.ga4_obfuscated_sample_ecommerce.events_*. Start with a small date range and inspect the schema before developing funnel logic.

Metrics

  • Users and sessions by source, medium, and campaign when those fields are available and correctly extracted
  • Product view, add-to-cart and purchase funnel, with event definitions documented
  • Purchase event counts and purchase value, validated against the chosen schema
  • Cost per acquisition and ROAS only if reliable campaign spend and attributable conversions are available

ROAS requires a valid campaign-spend dataset and attributable revenue. It is not reported until those inputs are available.

Data quality

Record the test name, run timestamp, affected row count, severity, and resolution for each validation.

CheckRuleSeverity
Missing user identifiersuser_pseudo_id IS NULL per day and eventHigh
Duplicated transaction IDsMore than one purchase event per transactionHigh
Unexpected event volumeDaily rows outside a documented baseline rangeMedium
Stale dataNo events for the latest expected dateMedium

Severity levels are proposed and will be confirmed when the checks run.

SQL and dashboard

Start with the SQL starter template, which profiles event rows and missing user IDs over one week. The published dashboard URL and findings will be added only after validation.
